# Migrating an existing game to v2.0.0

v2 adds automatic WebGPU → WebGL 2 startup fallback. Its backend-neutral
renderer API changes custom rendering integrations, so this is a major release.
New copies of the template, the blank game and Starter Arena are already
adapted. For renderer behavior and supported features, see
[the starter guide](../starter.md#rendering).

## Model draws and render hooks

Before, a hook received a WebGPU render pass:

```ts
renderer.sceneHooks.push((pass) => models.draw(pass));
```

After, the selected model driver binds its own resources and current pass:

```ts
renderer.sceneHooks.push(() => models.draw());
```

`SceneHook` and `ShadowHook` both take no arguments. `models.drawShadow()` also
takes no arguments. `ModelRenderer` registers its shadow hook in its
constructor; do not add a second hook for the same model renderer.

The shared `GpuModel` name is retained for imports, but fields such as
`nodeBuffer`, `jointBuffer`, `bindGroup`, `textureGroups` and `textures` are no
longer WebGPU resources exposed to game code. Use `upload`, `instance`,
`prepareStatic`, `prepareSkinned`, `recolor` and `retexture` on `ModelRenderer`.
Move custom resource handling into a backend driver. The shared `ModelDriver`
contract is in [src/gpu/model.ts](../../src/gpu/model.ts).

## Canvas ownership during boot

A canvas that acquired WebGPU cannot then acquire a WebGL context. On a failed
WebGPU attempt, selection replaces it with a fresh canvas that copies its
attributes. Bind input, orbit controls and any canvas listeners **after**
selection, using the returned canvas:

```ts
const renderer = await Renderer.create(originalCanvas);
const canvas = renderer.canvas;
const input = new Input(canvas, actions);
```

Use that same `canvas` for sizing, focus, projection and calls to
`renderer.render(canvas, frame)`. Do not retain listeners or references to the
original element. `GameRuntime.boot()` and the bundled previewer handle this
already; this change matters to custom boot code.

Remove boot guards that reject a missing `navigator.gpu` or insecure context
before selection. WebGL 2 may still work there. Use HTTPS for production and
for WebGPU testing on a phone over LAN (`npm run dev:https`).

## Completion, errors and capabilities

| v1 integration | v2 integration |
| --- | --- |
| `renderer.device.queue.onSubmittedWorkDone()` | `renderer.finished()` |
| Catch/import `WebGPUUnavailable` | Catch/import `GraphicsUnavailable` from `@engine/gpu/renderer` |
| Assume every renderer has a WebGPU device | Inspect `renderer.backend`, then use a backend driver |
| Assume HDR and bloom always work | Inspect `renderer.capabilities.hdr` and `.bloom` |

`renderer.info()` returns `{ backend, fallbackReason, hdr, bloom }`.
`fallbackReason` is `null` for direct selection, or the failed WebGPU stage
when WebGL was selected automatically. `__game.graphics()` exposes the same
information for browser checks and a game's own diagnostics.

`renderer.finished()` waits on either a WebGPU queue or a WebGL fence. This
also keeps `?capture` / `__game.step(n)` usable on both backends.
`renderer.dispose()` releases the selected renderer's resources. The runtime
handles graphics loss by stopping gameplay and showing reload guidance; it
does not restore a lost context or change backends during a round.

## Custom effects

Built-in models, instances and particles work through the shared renderer.
An effect that uses raw WebGPU pipelines, buffers or WGSL needs a WebGL
implementation to appear in the fallback path. The old `device`, `frameLayout`,
`frameBindGroup` and format accessors now belong to `WebGPURenderer`, while
WebGL drawing is implemented under `src/gpu/webgl/`.

Use `renderer.backend` to choose the effect driver, following the
[preview overlay](../../src/preview/overlay.ts). Keep WebGPU globals such as
`GPUBufferUsage` inside the WebGPU implementation, so loading the game does not
throw before the fallback can start. Backend imports used only for TypeScript
types should be `import type`. Read `WebGPURenderer.pass` only inside a render
hook; it is the current pass, not a persistent encoder for later work.

Games also own their analytics. If startup errors were previously labeled
“WebGPU required,” adapt them to report final graphics failure and successful
fallback separately, using `renderer.info()` where useful. The template does
not install or migrate a Convex backend.

## Verify the migrated game

Run from the repository root, selecting your game's folder:

```sh
GAME_DIR=addons/starter-arena npm run build
GAME_DIR=addons/starter-arena npm run test:game
GAME_DIR=addons/starter-arena npm run smoke
GAME_DIR=addons/starter-arena npm run test:graphics
```

The full browser checks need Chrome with both APIs available. For a WebGL-only
machine, run `npm run smoke -- --renderer=webgl2` with the same `GAME_DIR`.
The new smoke filenames include the backend, for example
`out/smoke/starter-arena/webgl2-desktop-play.png`; update capture consumers that
expect the old `desktop-play.png` names.

Also force `?renderer=webgl2` while checking the game's custom effects and
preview models. The fallback tests inject missing API/adapter/device and
initialization failures, verify replacement-canvas input and resize, exercise
WebGL without usable float targets, and check context loss. Check actual
unsupported devices and the intended host separately; injected failures and
phone emulation do not establish those results.
